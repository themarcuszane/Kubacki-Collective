## Content path confinement

`lib/content.ts` accepts only known content collections and lowercase hyphenated slugs found in regular `.md` or `.mdx` files. It resolves each file and checks containment beneath the selected content root. Drafts are filtered before slug generation and direct reads, so they cannot enter indexes or static params. Chapter and journal dynamic routes set `dynamicParams = false`.

The MDX source remains trusted repository code executed during the build. It is not visitor input. Regression coverage exercises normal content, unknown and traversal slugs, slash and backslash separators, encoded and double-encoded forms, absolute paths, NUL bytes, drafts, and symlink escapes using temporary fixtures.

## CI and scanning

- Existing Node.js 24, Ubuntu 24.04, pinned checkout/setup/browser actions, and the `test` job are preserved.
- Independent `dependency-audit` checks run `npm audit --audit-level=low` for the full tree and production tree. These enforce zero npm advisories; thresholds are not relaxed.
- `source-and-artifact-secrets` scans all Git history and the exact tested public ZIP using upstream Gitleaks 8.30.1. CI checks the Linux x64 archive's pinned SHA-256 (`551f6fc83ea457d62a0d98237cbad105af8d557003051f41f3e7ca7b3f2470eb`) against the [upstream release checksum file](https://github.com/gitleaks/gitleaks/releases/download/v8.30.1/gitleaks_8.30.1_checksums.txt) before execution. No broad ignore rule was introduced.
- A dedicated CI job analyzes JavaScript/TypeScript using the official `security-extended` query suite on PRs and main pushes.
- Dependabot checks npm and GitHub Actions weekly. Existing repository protections and secret scanning settings are unchanged.

## Release artifact and provenance

The existing isolated build allowlist remains the boundary for public source files. After tests pass, CI verifies every exported file against `out.manifest.json`, then uploads only the public ZIP, manifest, and `SHA256SUMS`. `.next`, Git metadata, environment files, reports, and local build state are excluded. On successful pushes to `main`, a separate least-privilege job verifies checksums and attests the ZIP and manifest using GitHub artifact attestations. PR jobs have no OIDC or attestation write permissions. No AWS credentials or deployment step is present in CI.

The release runbook requires operators to verify checksums and both attestations, check the source commit and clean-build marker, extract the exact archive, and provide the reviewed manifest SHA-256 for `scripts/deploy-public.mjs --apply`. The script checks that digest before uploads. There is no automated production deploy.
